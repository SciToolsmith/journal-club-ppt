# 模板组件维护

仅在更新模板或修复组件时读取。普通文献汇报使用已有组件，不重新生成模板。

公开包中的 `assets/k105-blue/starter.pptx` 是由 `scripts/deck_components.mjs` 生成的干净版式示意。`starter-manifest.json` 记录来源组件、文件散列、运行时与实际检查范围；`layout-catalog.json` 保留页面计划使用的语义版式 ID。

## 更新与验收

1. 先定位受影响的原生组件，核对正文与导航、图注、表格、流程及主题的一致性。每次变更保持实际用户页数和科研原图不受模板维护影响。
2. 按 [build-api.md](build-api.md) 的模板维护命令生成并检查实际导出文件。运行材料放在独立维护目录，不能进入公开仓库或用户交付目录。
3. 默认渲染全部9类版式。只改局部时，可选择受影响页面并记录其余页面沿用检查的依据；改色、字体或全局几何后须完整检查。
4. 检查原生文字、表格与连线、字号、缺字、重叠、裁切和内容分布。修改后更新散列；只有实际查看后才能填写视觉审阅通过。
5. 模板只保留编辑标签和必要导航示意。真实论文、作者、期刊、实验图和数值由任务输入填充，不写入共享 starter。

## 本地参考材料

原始参考 PPT、原版截图及其中的示例论文不随公开包分发。常规生成和模板维护均可只用原生组件运行。

维护者如有可使用的原件，可放在已忽略的 `assets/k105-blue/reference.pptx` 路径，用于本地对照；脚本只读取其散列，不修改或发布原件。原件不存在时清单中的 `reference_sha256` 为 null，不能声称本次已对照原件。原件的名称或散列仅说明设计来源，不授予再分发许可。
