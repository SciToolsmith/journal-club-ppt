# 内容、成品与交付检查

规划进入制作时读“制作中”，交付前读“最终文件”；复核字段与散列绑定以 [data-contract.md](data-contract.md) 为准。

## 制作中：先查容易返工的页面

首轮预览覆盖实际采用的 layout 变体，例如单/多图、不同表格或方法结构，并检查稀疏文字、宽/竖图、密集图、公式及 custom 页面；同一 render.type 不代表相同布局风险。查看构建回执的 `layout_diagnostics` 和补入代表预览的页面，依据 [layout-composition.md](layout-composition.md) 修复内容分布与分组关系。局部修改只复查受影响页，共用组件修改则检查所有使用页；不重复渲染未变内容，也不用代表页代替独特或密集页。

普通任务不重审整套原始模板；组件、工具版本变化或出现失真时，才与原始参考核对受影响版式。

科学检查重点：

- 既有全文及全主图主表审阅记录真实完整；关键数字、单位、组别、条件与不确定性符合原文，命名字段不能代替核验。
- 方法的输入、目标、关键求解、输出、停止条件连贯；流程的更新顺序、回环落点和继续/终止分支准确，公式符号、索引、上下标与运算关系无误。未展示环节有真实理由。
- 保留会改变结论的对照、负结果与边界；作者陈述、阅读分析和假设可区分，跨篇条件不足时不直接排名或合并结果。

独立核对适用于有科学收益的疑点，如关键数字、对照条件、难辨图或结论强度。只提供必要原文定位/片段、待核对结论及相关页面的最小上下文；若核对视觉表达，再提供该页或局部渲染。要求返回具体问题与依据，不重复生成全文摘要或完整分析报告；需要时再扩展材料范围。不要为省 token 取消有价值的针对性复核，也不要求每篇固定数量的独立代理。

## 最终文件：完整渲染并逐页查看

检查实际导出的最终 PPTX，不能只看生成前画布或中途代表页。逐页确认：

- 构图通过：没有无意义的大空白、正文挤在一端、左右失衡或图文脱节；信息有主次，核心证据大小合适。大片空白必须重排，不能因文字不溢出就记为通过。`layout_checked` 同时包含美观与内容分布检查。
- 封面主色横带上方没有文字，不出现额外的汇报类型眉题；该处模板留白不作为填充内容的空间。
- 标题、正文、图注无缺字、截断、重叠或孤立标点，数字和单位换行不改变含义。左上栏目与页内主题清楚，编号、来源归属正确，同栏目连续页一致，标题区未挤掉必要证据。
- 图内首末刻度、坐标、单位、图例、面板与统计标记完整可读，图注指向正确实验。主要图证据获得足够空间，读图提示准确且不遮图。
- 方法箭头和回环表达真实算法，公式符号及条件在渲染后仍正确。总结回答研究问题，贡献、边界和讨论有主次，未被结束页取代。
- 标题、说明、来源、表格与简单流程为原生可编辑对象，科研图为独立可替换图片。
- 页数、页码、导航、目录目标与计划一致，默认结构或具体例外符合数据契约；无模板示例、旧论文残留或姓名日期占位。固定末页符合 [template-use.md](template-use.md)。
- 实际主题符合用户确认，封面、标题、角标、目录、表格、流程与结束页统一，科研原图颜色未改；新任务没有借旧版蓝色兼容规则代替回答。

发现问题时回到对应证据、计划或组件修复，再检查受影响内容与全稿结构；按数据契约更新 review.json，不能只更新散列或让脚本预填通过。改色须重新制作并查看全部导出页。

保留执行成本低的 check-plan、check-pptx、finalize，不以缓存跳过；它们不能判断科学真假或视觉质量。finalize 通过后仅交付一个 PPTX，渲染 PDF、图片、回执、分析与脚本留在内部。
